## ADDED Requirements

### Requirement: No OS-level scheduling
The generated Tier 1 prohibitions MUST forbid creating, installing or editing operating-system schedules in any form (cron/anacron/`at`, systemd timers, launchd agents or daemons, Windows Task Scheduler) and MUST state that scheduling lives in the application.

#### Scenario: Prohibition present in generated specs
Given a project generated by rulebook
When the prohibitions spec is rendered
Then it contains a "No OS-level scheduling" prohibition naming cron, systemd timers, launchd and Task Scheduler

#### Scenario: Clause present in always-loaded context
Given a project generated by rulebook
When CLAUDE.md and the lean AGENTS.md are rendered
Then each contains a clause that scheduling belongs in the application and OS schedules are never created, and the always-loaded context budget still holds

### Requirement: Scheduler guard
The system SHALL install an optional PreToolUse guard that denies `Bash` commands which create or install OS schedules and denies `Edit`/`Write` targets under OS scheduler directories, allowing everything else without inspection beyond a keyword prefilter.

#### Scenario: crontab denied
Given the guard is installed
When a Bash tool call runs `crontab -e` or `(crontab -l; echo "* * * * * job") | crontab -`
Then the guard returns permissionDecision "deny" with a reason pointing to application scheduling

#### Scenario: schtasks and PowerShell scheduled tasks denied
Given the guard is installed
When a Bash tool call runs `schtasks /create ...` or `Register-ScheduledTask ...`
Then the guard denies it

#### Scenario: systemd timer and launchd denied
Given the guard is installed
When a Bash tool call runs `systemctl enable --now backup.timer` or `launchctl load ~/Library/LaunchAgents/x.plist`
Then the guard denies it

#### Scenario: Unrelated commands allowed
Given the guard is installed
When a Bash tool call runs `npm test` or mentions "cron" only in a comment string such as `grep cron README.md`
Then the guard allows it

#### Scenario: Scheduler paths denied on write
Given the guard is installed
When an Edit or Write targets `/etc/cron.d/job`, `~/Library/LaunchAgents/x.plist` or `/etc/systemd/system/x.timer`
Then the guard denies it, while a write to `src/jobs/scheduler.ts` is allowed

### Requirement: Guard wiring
`applyClaudeSettings` SHALL accept `osSchedulingGuard`; when true it installs the script into `.claude/hooks/` and upserts one PreToolUse entry with matcher `Bash|Edit|Write`; when false or absent it removes that entry. `rulebook init`, `rulebook update` and `rulebook claude` MUST enable it.

#### Scenario: Both guards coexist
Given taskScaffoldingGuard and osSchedulingGuard are both desired
When settings are applied twice
Then PreToolUse has exactly two entries, one per guard, and the second apply changes nothing
