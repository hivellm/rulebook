# Proposal: phase1_update-cleanup

## Why
`rulebook update` keeps v5/v6 rules, agents and skills that lack the "Generated by" marker (Synap pays 5,676 rulebook tokens per session and per spawn vs 1,914 clean, with rules that contradict v7.4), manages only four hook events (retired hook entries keep failing: UzEngine 269 errors per session) and never refreshes agents (this repo's implementer says it writes Rust) (docs/analysis/multi-session-performance/04-context-and-orchestration.md F-030; 06 F-041, F-042; 01 F-006).

## What Changes
- Content-hash catalogue of every rule, agent, skill and hook script shipped since v5, built from git tags at build time.
- Matches move to `.rulebook/backup/`; edited files are kept and reported.
- Manage all hook events and settings.local.json; strip entries whose script file is missing.
- Refresh rulebook-shipped agents and skills; fix the language substitution in agent templates.

## Impact
- Affected specs: docs/analysis/multi-session-performance/08-execution-plan.md
- Affected code: src/core/migration/v6-cleanup.ts, src/core/claude/claude-settings-manager.ts, src/core/claude/claude-mcp.ts, src/cli/commands/update.ts, scripts/ (catalogue build), tests/update*.test.ts
- Breaking change: NO (moves to backup, never deletes edited files)
- User benefit: Rulebook-attributable tokens in upgraded projects ≤ 2,100 (from 4.5–5.7 k); contradicting v6 rules gone; no failing retired hooks.
